Unauthorized message storage

Start from a damaged copy of a template and repair it. Template: Real-Time Application.

Scenario

A socket now writes to storage without message checks; a can also write directly. The proper persistence edge disappeared.

Tasks

  1. Remove users→persist and socket→persist shortcuts.
  2. Restore messages→persist route.
  3. Explain room membership validation and lost-ack replay.

What to check in your answer

  • cannot write directly to storage.
  • Messages can be acknowledged only under a defined durability rule.
